Apps loaded through the module server (apps with `autoUpdates: true`) now send unexpected SDK errors to Sanity's error tracking, through the `api.sanity.io` intake tunnel. `@sanity/sdk` adds `@sentry/browser` as a dependency, loaded lazily only when reporting is on.

Only errors thrown by SDK code and caught by the `SDKProvider` or `AuthBoundary` error boundaries are reported. Errors from your own components, expected SDK errors (document actions, message bus, Sanity API 4xx and 5xx responses, network failures, aborted requests), authentication and configuration errors, and CORS errors are not. Each event carries the error, its stack, the SDK version, the boundary name, and the React component stack. It carries no cookies, headers, request bodies, user data, or IP address. A page sends at most 10 events.

Apps that do not use auto-updates send nothing. To turn reporting on while debugging, set `localStorage.SANITY_DEBUG_ERROR_REPORTING`.
